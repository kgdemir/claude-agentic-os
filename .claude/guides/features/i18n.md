# Culture, text and time (i18n)

Applies to projects that parse or format numbers and dates, compare or case-convert strings, store
times, or show text in more than one language. SQL Server collations:
`~/.claude/guides/tools/sql-server.md`.

- **Machine data uses the invariant culture; people see their own culture.** Parse and format config, file formats, logs and API payloads with `CultureInfo.InvariantCulture` (.NET) or a fixed locale; format display text with the user's culture (`Intl.NumberFormat`, `Intl.DateTimeFormat` in JS).
  *Why: `double.Parse("1.5")` returns `15` where `.` groups thousands (`tr-TR`, `de-DE`) and throws `FormatException` where a space does (`fr-FR`); the bug appears only on that machine.*
- **Identifiers are compared and case-converted ordinally,** never with the current culture: `StringComparison.Ordinal` / `OrdinalIgnoreCase`, `ToUpperInvariant()`, `ToLowerInvariant()`.
  *Why: the Turkish-I problem: under `tr-TR`, `"FILE".ToLower()` is `"fıle"` and `"file".ToUpper()` is `"FİLE"`, so keys, headers and file extensions stop matching.*
- **.NET: make the analyzers enforce it.** Set `CA1304`, `CA1305`, `CA1307`, `CA1309`, `CA1310`, `CA1311` to `error` in `.editorconfig` (`dotnet_diagnostic.CA1305.severity = error`).
  *Why: every culture-sensitive overload looks correct in review; only the analyzer sees them all.*
- **User-facing text is sorted and compared with the user's locale:** `string.Compare(a, b, culture, CompareOptions…)`, `Intl.Collator`, `localeCompare(b, 'tr')`, and case-converted with `toLocaleUpperCase('tr')` when the text is Turkish.
  *Why: ordinal sorting puts `Ç`, `Ğ`, `İ`, `Ö`, `Ş`, `Ü` after `Z`.*
- **Containers keep the culture data the app needs.** Check `InvariantGlobalization` in the project and `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT` in the image; Alpine-based .NET images set `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=true`, so they need both `apk add icu-libs` and `ENV DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=false` (or a non-Alpine image).
  *Why: in invariant mode every culture behaves like the invariant one, so culture-aware sorting and formatting silently stop working only in production.*
- **Store times in UTC; convert at the edge.** Keep the user's IANA time zone id (`Europe/Istanbul`) when local time matters; `DateTimeOffset` over `DateTime` in .NET.
  *Why: a local time without its zone cannot be converted correctly after a daylight-saving change or a server move.*
- **Text lives in resource files** (`.resx`, i18next JSON, gettext), with whole sentences and named placeholders; plurals and gender through ICU MessageFormat or the library's plural rules.
  *Why: concatenated fragments cannot be reordered for another language's grammar.*
- **Normalise user-entered Unicode to NFC** before comparing or storing it as a key.
  *Why: `é` typed as one code point and as `e` + combining accent look identical and compare unequal.*
